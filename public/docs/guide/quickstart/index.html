入门 / 快速开始

快速开始

启动 CHARACTOID 展示站，了解角色、知识、声音与工具如何组成一个可恢复的 Agent 工作台。

安装与运行 ​

需要 Node.js 18 或更高版本。在项目目录执行：

git clone git@github.com:TKGEKKOU/charactoid-product-site.git
cd charactoid-product-site
npm install
npm run dev

开发服务器默认运行在 http://127.0.0.1:18080/。生产构建使用 npm run build。

配置角色 ​

页面当前以静态演示数据展示角色 Agent 的工作方式。你可以从 public/assets 替换 Logo、音频与 Live2D 素材，并在 src/main.js 中调整展示内容。

理解系统结构 ​

CHARACTOID 将自然语言请求拆分为可追踪的运行过程：

  1. 角色层：保存角色设定、知识、声音与交互风格。
  2. 协调层：负责理解请求、选择 Worker，并维护任务状态。
  3. 执行层：通过 RVC、检索、工具或 Live2D 相关能力完成具体工作。
  4. 结果层：将文本、音频或文件资产关联到本次 run_id 并返回对话。

继续开发 Worker ​

展示站不包含后端运行时。接入真实系统时，建议让前端只提交结构化操作，由后端 Worker 负责文件、模型和任务执行，并返回状态事件与资产引用。

下一步 ​

继续阅读项目源码，或从首页的 RVC 文件工作流、资源生态和能力边界开始了解完整设计。

Python SDK ​

后端接入时，可以围绕一次 run_id 组织任务。前端展示层只消费状态事件和资产引用，不直接处理本地路径或 Shell。

from charactoid import Client

run = client.runs.create(character="miku", input="生成一段语音")
for event in run.events():
    print(event.type, event.data)

自动化与会话提醒 ​

自动化能力适合把重复任务变成可追踪的会话动作：触发条件进入任务队列，Worker 执行后回写状态，失败时保留重试入口。

接入记忆 MCP ​

记忆服务可以作为 MCP 工具接入。建议将工具描述、输入 schema、权限范围和返回结构明确记录，避免 Agent 依赖未声明的副作用。

Agent 生命周期 ​

一次运行通常经过 queued → running → waiting_input → completed，也可能进入 failed、cancelled 或 retrying。每个状态都应能被恢复和解释。

API 与事件 ​

推荐使用结构化事件传递进度：run.created、worker.started、asset.created、run.completed。资产通过 asset_id 与运行关联。

运行边界 ​

当前仓库是纯前端产品展示项目，不包含实际模型推理、文件处理或后端任务调度。页面中的 RVC、GPT-SoVITS、RAG 与 Live2D 内容用于展示接入方式和产品边界。
